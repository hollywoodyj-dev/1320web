## 3｜NOVA 的潤色方式：改語言，不改主題

### 3.1 要達成的讀感

- **像一份值得收藏的生命藍圖解讀**：讀者讀得懂「這個 Code 究竟是什麼」，而不只是被稱讚。
- **平易但不淺薄**：日常場景能自然說明原型，重要的觀念解釋夠充分。
- **有溫度、有親和力，但不煽情**：像成熟、仔細的作者在跟讀者說清楚一件事。
- **有辨識度**：258 碼都有自己的主題、例子與課題；不能套同一段「你要學會愛自己」。
- **有啟發而不自封真相**：讓讀者從生活經驗自行認出是否相符，保留不認同、修改和選擇的權利。
- **標準台灣繁體中文（zh-TW）**：用詞自然、閱讀順暢，避免生硬英譯或簡體中文口吻。

### 3.2 請具體改掉的 AI 痕跡

| 舊稿容易出現的問題 | NOVA 需改善 |
|---|---|
| 每段都說「這個原型象徵……」「它的作用是……」 | 保留標題，但段落內更自然地展開；少用同一開頭 |
| 大量「不是 A，而是 B」「你不需要 X」 | 只在真正需要界定概念時使用；其他地方用直接、平實的敘述 |
| 套公式：「你有天賦 → 你的陰影 → 你學會放下」 | 根據**該碼來源**建立不同論述與情境 |
| 抽象詞連發：「頻率、能量、宇宙、蛻變、覺醒」 | 優先解釋成看得見的行為、互動、選擇與生活場景 |
| 空泛假設：「在工作中你可能有壓力」 | 具體到例如：一場會議、一則訊息、一項交接、一段溝通 |
| 裝懂讀者：「你小時候受傷，所以……」 | 改成清楚標記為「假設」「有些情境中」，不編造經歷 |
| 只增加形容詞來拉長篇幅 | 增加理解深度與真實可想像的細節，避免冗長與重複 |
| 結尾喊口號或直接下人生結論 | 以一個能與章節主題相呼應的理解和具體提問收束 |

**重要：不要把所有否定句清除。** 需要界定宿命、醫療、關係安全、財務聲明時，應準確保留。

### 3.3 RC3 的寫作示範：學習方法，不複製文字

參照 S1-18「轉化者」：
- 先清楚說明「改變」與「轉化」有何差別；
- 再說明核心價值與存在於 S1 的作用；
- 接著解釋可能的力量與課題；
- 透過**工作流程失效**與**自我要求過高**兩個不同假設情境，使讀者理解；
- 最後有經過前文鋪墊的領悟與反思。

**禁止：** 複製「什麼值得保留、什麼需要改變」作為其他 257 碼的標準結尾。各碼須從自己的定義自然長出不同的洞察。

- 四碼／十碼整合有沒有提供新增的理解，而非重複內容？
- 讀者是否保有主權、讀完能帶走一個可實踐的觀察？
- 是否仍有重複、僵硬、過度心靈雞湯、假裝深刻的句子？

**不得把「自動 QA 全通過」當成「真人閱讀通過」，更不得當成正式 APPROVED。**

## 9｜強制版本閘門與禁止操作

## 10｜完成定義與 NOVA 應回報的內容

每一階段結束，請向內容負責人交付：
1. `deliverable_manifest`：檔案清單、版本 ID、SHA-256；
2. `structural_diff`：原結構與新稿一一對應，列出任何變動；
3. `source_trace_report`：每碼來源與語義涵蓋，S5／S6 七欄保留；
4. `safety_gate_report`：固定安全句與沒有越界承諾的檢查；
5. `human_reading_queue`：尚待真人閱讀／明確需修改的項目；
6. `protected_preview_links`：僅限內部存取，不能當作顧客已發布證據；
7. `rollback_reference`：任何新版不被接受時，可回到 RC1／RC3 或原候選資料。

**最終成功標準：** 讀者看到原本完整的報告架構，卻能更順暢地理解每一個原型；文字有深度、有生活感、可產生體會，仍忠於來源、尊重自主且可追溯。**只改語言，不能改變產品底層或審閱權限。**
