## 0. 問題與不能誤判之處

編輯負責人的回饋：**「現在出來的 SAMPLE REPORT 的內容是很少的。」**

目前可開啟 `/tw/free-soul-blueprint` 的介紹頁，但外部工具無法直接驗證生日表單送出後的所有動態輸出。因此**尚未確定**是哪一種技術原因：
- 前端本來就只顯示 `summary`／`short_description`；
- API 只取了 `preview_excerpt` 而沒有取 `narrative_body`；
- 報告正文存在但 UI 設有 `maxLength`、`slice()`、CSS 行數截斷、折疊狀態；
- 因 Code 文案未核准而使用了簡短 fallback；
- 把英文官網的 **locked Sample Preview**（選讀節錄）當作 TW **完整 Free Sample Report** 來實作。

NOVA 必須記錄**真正原因＋發生位置＋前後驗證**；不得只靠增加幾句話掩蓋資料傳遞問題。

## 1. 正確的產品／內容區分

### A. 免費生命映照（簡短試看）

若此名稱指首頁上一段簡短介紹或基本生日結果，這本身可以短，但應明白稱為「簡短映照」或「Code 概覽」。
**不得標示為完整 RC3 Free Sample Report**。

### B. Free Sample Report（完整四碼樣本）

這是本次修正目標：固定七個章節、四個 Code 全文、自然且可獨立閱讀。
若 NOVA 的既有受保護 Preview 某區塊名為 Sample Report，就必須以這個標準顯示，或清楚標註仍屬「縮略預覽」。

### C. Full Report（十碼 17 章）

S4–S9 以及完整十碼整合，屬於 Full 結構。**不以刪掉免費四碼的定義／案例製造付費價值差異。**
注意：Free／Full 公開產品權限目前尚待產品負責人確認；不能藉這次修正改動正式站權限與價格。

## 2. Free Sample Report 固定內容及章序（嚴禁縮短）

| 章 | 必須有的內容 |
|---|---|
| 開頭 | 生日、完整 Code 與名稱總覽、必要的象徵性聲明 |
| 01 | S1：完整單碼解讀 |
| 02 | S3：完整單碼解讀 |
| 03 | S2：完整單碼解讀，固定關係安全句逐字保留 |
| 04 | S0：完整單碼解讀 |
| 05 | 四碼整合：**至少兩條由此生日實際 Code 引出的跨碼連結**，有一個可理解的生活情境 |
| 06 | 至少三個能連回日常的反思問題 |
| 07 | 有價值、有完整感的結語；不得恐嚇式轉換或宣稱未購買就無法理解自己 |

### 每碼固定七項內容（參照 RC3）

1. `這個原型是什麼？`：完整定義與象徵代表意義。
2. `它在生命藍圖中的作用與目的`：核心價值、模組作用。
3. `可以探索的力量`：可能的資源與優勢，清楚而不誇大。
4. `可能的內在張力與主要人生課題`：具體的生活難處、界線。
5. `日常生活對照（以下均為假設案例）`：**兩則不同、可想像的日常情境**。
6. `可帶走的領悟`：有前文推導而來的觀點。
7. `留給自己的問題`：有辨識度、可自行核對的反思。

**不可用以下內容替代單碼正文：** 一句 Code slogan、三個 tag、100 字摘要、模組名稱表、只顯示「優勢／陰影」短詞、模糊的「你需要放下」套句。

## 4. 前端與 API 修復步驟

1. **先稽核**：使用受保護 Preview，分別開啟 1980、1982、1983 的 Free Sample，以 Network／React DevTools／server logs 定位輸出欄位與截斷點。留存前後證據。
2. **確認資料層**：長文正文是否已按 `code_id`／`version_id` 保存？如只有摘要，正確接入長文候選資料；**不能把未核准長文導入正式顧客 API**。
3. **確認 render**：分章提供可滾動、可導覽的完整閱讀頁；長文需支持段落、次級標題、情境一／二、提示／安全句，手機不因卡片高度而截斷。
4. **確認字體／排版**：繁體中文建議適度行高、段落間距與舒適行長；不要用 CSS `line-clamp`、固定高度＋`overflow:hidden` 隱藏章節正文。可以有「目錄收合」，但不應造成正文內容消失。
5. **確認資料缺失行為**：正式資料未通過核准時，顯示「內容待審／無法正式提供」，不得用一兩句臨時 AI 文本冒充完成報告。
6. **確認 Full 差異**：Free 四碼已完整，Full 的差異是另外六碼、跨層整合、七日練習與日誌；Full 第 07 章可深化，但原有章序不得改。

## 5. 品質閘門（自動 QA + 真人閱讀分開）

**Auto QA**
- 7／7 章；S1→S3→S2→S0，沒有 S4～S9 章節正文。
- 4 個 Code 皆為**該生日實際計算結果**；不複製其他生日內文。
- 每碼都有七段完整主題、兩則不同的假設案例。
- S2 原句必須原字出現：`如果關係裡存在威脅、操控或傷害，保護自身安全比尋找任何『靈魂意義』更重要。`
- Code source hash 可追溯；無內部欄位洩漏；候選不發布。
- 三組黃金樣本在受保護 Preview 的正文與附件一致（忽略排版標記、UI 標籤、純 Markdown 格式差異），不得缺段。
- 桌面／手機均能透過目錄讀完各章，不能存在被 CSS 截斷的內容。

**Human Reading**
- 讀者能準確回答四個 Code 各自代表什麼、核心價值是什麼、人生課題是什麼。
- 生活情境清楚、自然、有啟發，不裝作知道讀者的真實人生。
- 四碼整合提供至少兩條新理解，而不只是重述單碼摘要。
- 讀完免費報告有完整感，不會覺得只讀到了行銷文案。
- 語氣貼近已肯定的 1980 RC3，不因機器壓縮又變成 AI 模板。
