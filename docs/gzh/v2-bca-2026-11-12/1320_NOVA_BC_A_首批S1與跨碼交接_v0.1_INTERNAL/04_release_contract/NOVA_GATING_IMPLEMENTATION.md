# NOVA｜Preview 與顧客交付白名單

## 一、內部審閱 Preview

可以為任意有效生日計算 Code；**候選敘事**只能給已驗證的編輯／QA 成員檢閱。介面需清楚註記「內部審閱候選、未核准」，不進公開網頁、金流、顧客下載、行銷預覽或對外快取。

若某個 Code 沒有候選敘事，可將其標為缺口；不擅自從其他 Code/出生日期補齊。內部可依候選庫生成 **只用於比較的草稿**，但不可宣稱完成正式版。

## 二、正式顧客交付

維持全面 HOLD，直到產品負責人獨立核准。每個報告需要的每個 Code 和跨碼主張都經實際內容審核且使用**同一份** approved snapshot/rule set。任一缺漏，回覆 `BLOCKED_NO_APPROVED_SOURCE`。

`PENDING_REVIEW`、`NEEDS_REVISION`、`REJECTED`、缺 reviewer、缺 approved_at、或任何 `approval_id=PENDING_NO_APPROVAL` 一律不能進正式顧客端。

## 三、模型與資料權限

- 原始英文與編輯來源欄位屬機密；只有已核准顧客段落能進渲染白名單。
- 顧客輸出絕不暴露計算算法、原文來源欄位、映射方法、來源哈希、審核註記、內部版本或 claim ID。
- 不得將 fixture 人工文案換生日套用；若不同生日的 **十碼全部相同**，且無其他個人化資料，敘事語義可以接近。
- 讀者當下的生活狀態只能由讀者自願提供；不得從生日推論其人生經歷。
- S2 安全優先，S4 高風險事項必守專業標準。
- 版本命名中的 `approved` 僅能在真實審核完成後使用；目前不得建立任何 production-approved snapshot。
