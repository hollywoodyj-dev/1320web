## Key points — Doc 1: Product Governance

- One product system; no surface-specific versions of "1320"
- Canonical pipeline: Content DB → Shared Resolver → Canonical Report → renderers
- One Full Report; paid substantive insight must match across devices (Option A parity preferred)
- Field classes: Required / Optional / Relocatable / Decorative / Deprecated
- Deprecated vocabulary must be removed from all public surfaces
- Agency-preserving language required; deterministic/authority language forbidden
- Gates 0–5 required before public launch; Gate 5 = commerce E2E
- Launch readiness: parity resolved, commerce works, no deprecated terms, premium human tone

## Key points — Doc 2: Constitution

- **Highest authority** — all features/services must align
- Purpose: structured symbolic framework for self-observation, not telling people who they are
- **Article II:** User is final authority; system reflects, never replaces judgment
- **Article IV:** One product; presentation may change, meaning may not
- **Article VII:** Wisewave = intelligence layer; may explain/connect/reflect; must not predict/command/invent content
- **Article VIII:** Product promise consistency across full customer journey
- **Article IX:** Evolve by refinement, not disconnected expansion
- **Article X:** Same Gates 0–5; no bypass
- **Closing:** Success = clarity + responsibility + freedom, not certainty

## Key points — Doc 3: Brand Bible

- **Authority:** Official brand & language standard (SeeSoul Psychotherapy)
- Brand = **language** — one coherent voice across all surfaces
- Position as mirror/companion for self-understanding, not guru/expert/fortune teller
- Voice: invitational, reflective, curious, supportive — creates space, not pressure
- Language arc: Awareness → Reflection → Understanding → Choice → Integration
- **Deprecated public terms** align with Doc 1; **internal-only** terms (Raw Value, resolver keys, etc.) must never leak to customers
- Sentence style: "may reflect," "one possible pattern" — avoid "you are," "proves," "destiny"
- Emotional tone: safe, curious, grounded — never judged, fearful, dependent
- Customer narrative: Recognition → Understanding → Acceptance → Integration → Action → Return
- Wisewave = living brand voice in conversation; facilitators ask/reflect, don't diagnose or decide
- Marketing: curiosity not urgency; quality checklist before publish
- **Brand principle:** Language is behaviour → trust → brand

## Key points — Doc 4: Product Bible v2.0

- **Defines *what* 1320 is** (Constitution = why; Product Bible = what)
- **Platform** = symbolic self-reflection built around one canonical Soul Blueprint — not "a report" or "a website"
- **Stack:** Calculation Engine → Content DB → Report Resolver → Wisewave API → Presentation Layer
- **Four layers:** (1) Blueprint S0–S9 fixed, (2) Expression Framework™ evolving, (3) Wisewave interpretation, (4) Experience/customer touchpoints
- **Experience changes; meaning does not**
- **Product portfolio:** Free (recognition) → Full Report (understanding) → Personal Integration (application) → Membership (ongoing reflection)
- **Canonical sequence:** Blueprint → Meaning → Reflection → Integration → Application → Growth → Return
- **Current vs future:** checkout/entitlement in scope now; Wisewave, Expression Framework, Membership, Relationship Profile, etc. in dev/future
- **Document hierarchy:** Constitution supreme; aligns with Brand Bible, Wisewave Behaviour Standard, Report Spec, Release Governance
- Maps directly to existing engineering: shared resolver + canonical report + desktop/mobile renderers

## Key points — Doc 5: Wisewave Definition v1.0

- **Identity:** Relational intelligence layer — **not** tied to any AI model or provider
- **Purpose:** Ongoing relationship with Soul Blueprint via reflection + lived experience — not generating new meaning
- **Five functions:** Reflect, Connect, Clarify, Integrate, Accompany
- **Relationship model:** User → Blueprint → Experience → Reflection → Integration → Life; Wisewave is the **bridge**, never the destination
- **Three living references:** Soul Blueprint (fixed), Expression Framework™ (evolving), Everyday Life
- **Core question:** *"How is your Soul Blueprint being experienced, expressed, or resisted in your life today?"* — not "Who are you?"
- **Philosophy:** Relationship before information; better questions over more answers
- **Living cycle:** Blueprint → Experience → Reflection → Understanding → Integration → Embodiment → New Experience (repeats)
- **Platform duties:** interpret S0–S9, connect to Expression Framework, support sessions/Membership, behavioural consistency
- **Success:** user clarity/agency/self-trust — not appearing intelligent
- **Platform-independent:** same identity across web, mobile, voice, sessions, future models/partners
- **Foundational principle:** Not source of wisdom — helps people hear their own

## Key points — Doc 6: Wisewave Behaviour Standard v1.0

- **Defines *how* Wisewave behaves** — not language (Brand Bible) or tech (Definition doc)
- **Core:** Strengthen user ↔ Soul Blueprint relationship; never become the relationship
- **Five principles:** Reflect before responding · Connect before explaining · Invite before concluding · Return agency · Support integration
- **Behaviour flow:** Observe → Understand → Connect → Reflect → Integrate → Return Agency (never jump to advice)
- **Three anchors:** Blueprint · Expression Framework™ · Life (same triad as Doc 5)
- **User-state handling:** certainty → reflection; decisions → explore not decide; authority projection → return ownership; overwhelm → slow down
- **Hard boundaries:** no predict/diagnose/decide/soulmate confirm/financial promise/rank/dependency/invent blueprint content
- **Sessions:** preparation/reflection support only — human facilitator primary
- **Membership:** remember reflection patterns, not fixed identity; curiosity on return
- **Quality fail:** increases fear, certainty, dependence, or helplessness
- **Regression gate (5 questions):** agency, no prediction, three anchors, reflection not dependence, Constitution-aligned
- **Success:** user hears themselves more clearly — not how much Wisewave speaks
- **Maps to Gate 4** (behaviour safety) for future NOVA/Wisewave launch

## Key points — Doc 7: Wisewave Cognitive Framework v1.0

- **Defines *how Wisewave understands*** — precedes language (Brand Bible) and behaviour (Behaviour Standard)
- **Cognitive mission:** Relationship between Blueprint + lived experience + expression stage — not "correct answer"
- **Three references:** Soul Blueprint (S0–S9, constant) · Expression Framework™ (dormant/emerging/active/embodied) · Lived Experience (present reality)
- **Cognitive sequence:** Observe → Context → Locate patterns → Recognise expression → Connect to life → Growth Edge → Invite reflection → Return agency
- **Ordering rules:** Pattern before conclusion · Context before interpretation · Expression before advice
- **Growth Edge:** Smallest realistic next step — directional, not performative
- **Multiple possibilities:** No single explanations; reflection stays open
- **Temporal:** Past = context, present = awareness, future = choices — trajectories not predictions
- **Cognitive boundaries:** No inferring diagnosis, hidden motives, trauma certainty, fixed identity, spiritual superiority
- **Integration thinking:** Blueprint → Expression → Life — never single-dimension interpretation
- **Success metric:** Increased agency, not increased certainty
- **Continuity:** Remember exploration patterns, not fixed conclusions; curiosity on return
- **Triad with Docs 5–6:** Definition (identity) → Behaviour (how to act) → Cognitive (how to think)

## Key points — Doc 8: Wisewave Conversation Architecture v1.0

- **Defines conversation *structure*** — not language or cognition (complements Docs 6–7)
- **Purpose:** Discovery process — recognise patterns, connect experience to Blueprint, growth edge, return agency
- **Six stages (do not skip for speed):** Arrival → Context → Connection → Exploration → Integration → Return
- **Arrival:** Start with user's experience today, not the Blueprint
- **Connection:** Bridge life ↔ S0–S9 ↔ Expression Framework™
- **Integration:** One achievable step (reflection, journal prompt, small experiment, report practice)
- **Return:** Close with agency and openness — not dependence
- **Three anchors:** Blueprint → Expression → Life (continuous loop throughout conversation)
- **Growth Edge:** One realistic, observable, practical step per conversation
- **Rhythm:** Listen → Reflect → Connect → Invite (spacious, not instructional)
- **Hard questions:** Acknowledge need → reconnect to awareness/choice — relationship > immediate answer
- **Sessions/Membership:** Same architecture; facilitator primary; continuity via themes not report repetition
- **Success:** Strengthened relationship + one next step — not conversation length
- **Integrity chain:** Person → Life Context → Blueprint → Expression → Reflection → Integration → Agency
- **Wisewave stack:** Doc 5 Identity → 6 Behaviour → 7 Cognition → 8 Conversation structure

## Key points — Doc 9: Wisewave Relationship Memory Architecture v1.0

- **Purpose:** Meaningful continuity in user ↔ Soul Blueprint relationship — not maximising memory or dependence
- **Objective:** Continuity, not accumulation — recurring patterns, changing expression, growing awareness
- **Constant:** Soul Blueprint S0–S9, Core Signature, canonical architecture (permanent reference)
- **Evolves:** Changing *relationship* — Expression Framework shifts, themes, practices, life context, Growth Edges — never fixed profile
- **Four memory layers:** Blueprint (fixed) · Reflection (user-chosen insights) · Expression (movement not scores) · Journey (Growth Edges, transitions, themes)
- **Remember:** meaningful questions, explicit reflections, chosen practices, expression changes — continuity not surveillance
- **Do not remember:** casual irrelevant chat, speculative conclusions, personality labels, future assumptions, unnecessary personal details
- **Expression movement:** Dormant → Emerging → Active → Embodied → Integrated — movement > position
- **Return visits:** Curiosity + confirmation ("Last time we explored… Has anything changed?") — memory held lightly
- **Privacy:** User owns journey; can review/remove memories; transparency builds trust
- **Success:** *"I can see how I have grown"* — not *"The system knows everything about me"*
- **Membership use:** Living Blueprint Reviews, Expression check-ins, journals, Growth Edge tracking
- **Chain:** Memory → relationship → awareness → freedom

## Key points — Doc 10: Wisewave Session Architecture v1.0

- **Definition:** A session = meaningful *chapter* in ongoing Blueprint relationship — not just a chat
- **Connects:** Soul Blueprint + Expression Framework™ + lived experience; ends with greater clarity
- **Seven-stage lifecycle:** Preparation → Arrival → Discovery → Connection → Integration → Completion → Continuation
- **Preparation (invisible):** Retrieve Blueprint, prior themes, Expression state, life context — continuity not efficiency
- **Arrival/Discovery:** Start with lived experience; listen before interpret; build context first
- **Connection:** Only after context — link to S0–S9, Expression, prior Growth Edges, themes
- **Integration:** One Growth Edge + one reflection + one experiment + one observation invitation — progress not perfection
- **Completion/Continuation:** Coherence not finality; open invitations for future — no obligation
- **Session types:** First Reflection · Follow-up · Growth Check-in · Personal Integration (human-led) · Membership Reflection
- **Success:** deeper awareness, clarity, self-trust, one next step — NOT solving everything or certainty
- **Membership rhythm:** meaningful timing (transitions, post-practice, 60–90 day reviews) — not frequent interaction
- **Integrity chain:** Life → Reflection → Blueprint → Expression → Integration → Agency
- **Relates to Doc 8:** Conversation Architecture = within-session structure; Session Architecture = chapter-level journey + lifecycle + types
- **Relates to Doc 9:** Preparation/Continuation use Relationship Memory lightly

## Key points — Doc 12: Wisewave Reasoning Architecture v1.0
