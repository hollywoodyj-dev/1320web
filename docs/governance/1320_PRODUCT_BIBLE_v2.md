## 1. Purpose

The 1320 Product Bible defines the official architecture, structure, capabilities, and customer experience of the 1320 Platform.

This document exists to ensure that every product, feature, report, API, and future service remains part of one coherent platform.

- **The Constitution** defines *why* 1320 exists.
- **The Product Bible** defines *what* 1320 is.

---

## 2. Platform Definition

1320 is not a report. 1320 is not an AI. 1320 is not a website.

1320 is a **symbolic self-reflection platform** built around one canonical Soul Blueprint.

Everything else is an expression of that platform.

## 4. The Four Core Layers

The 1320 Platform consists of four interconnected layers.

### Layer One — Blueprint Layer

The permanent symbolic blueprint calculated from birth data.

Includes: S0 through S9.

This layer does not change. It represents symbolic structure rather than lived experience.

### Layer Two — Expression Layer

Defined by the **1320 Expression Framework™**.

Measures how the blueprint is currently being lived, integrated, resisted, or expressed.

This layer evolves over time. It supports future Membership, Personal Integration, and longitudinal reflection.

### Layer Three — Interpretation Layer

Powered by the **Wisewave API**.

Responsibilities include:

- explaining report content
- connecting symbolic patterns
- answering questions
- supporting reflection
- preserving ethical boundaries

Wisewave interprets. It never replaces the blueprint.

### Layer Four — Experience Layer

Every customer interaction belongs here.

Examples: Website, Reports, Mobile, PDF, Checkout, Email, Personal Integration Session, Future Applications.

**Experience changes. Meaning does not.**

Wisewave API is the intelligence layer of the platform.

## 8. Canonical Product Model

Every customer experience should preserve this sequence:

```text
Blueprint → Meaning → Reflection → Integration → Application → Growth → Return
```

No feature should bypass these stages.

---

## 9. Product Principles

Every new feature must strengthen at least one of:

- Awareness
- Reflection
- Agency
- Integration
- Long-term growth

Features that primarily increase dependency, certainty, or complexity should not be introduced.
