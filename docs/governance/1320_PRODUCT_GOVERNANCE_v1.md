# 1320 Product Governance

**产品治理总则 v1.0**

---

## 1. Core Principle

1320 is one product system.

Website, Free Report, Full Report, Mobile Report, Checkout, future NOVA AI, and Personal Integration Session must all express the same philosophy, vocabulary, boundaries, and product promise.

There must not be multiple versions of "1320" across different surfaces.

---

## 2. Product Definition

1320 is:

- a symbolic self-reflection system
- an awareness framework
- a pattern mirror
- a structured language for inner reflection
- a tool for integration, not prediction

1320 is not:

- fortune telling
- destiny reading
- therapy
- diagnosis
- financial advice
- legal advice
- spiritual ranking
- guaranteed transformation
- authority over user decisions

---

## 3. Product Architecture

All report experiences must follow one canonical structure.

```text
Content Database
       ↓
Shared Resolver
       ↓
Canonical Report Object
       ↓
Desktop Renderer
       ↓
Mobile Renderer
       ↓
PDF Renderer
       ↓
Future NOVA / AI Layer
       ↓
Personal Integration Support
```

Desktop and mobile may differ in layout.

They must not differ in meaning unless Product explicitly defines them as different products.

---

## 4. Canonical Report Rule

There is only one Full Report.

If a user purchases the Full Report, they must receive the same substantive insight regardless of device.

**Allowed differences:**

- layout
- pagination
- swipe vs scroll
- visual hierarchy
- collapsed sections
- reordered presentation

**Not allowed without documentation:**

- missing paid content
- thinner mobile meaning
- omitted modules
- different disclaimers
- reduced practice/journal sections
- hidden desktop-only insights

---

## 5. Product Tiers

### Free Report

**Purpose:** Build trust and curiosity.

It should help the user feel: *"This reflects something real enough that I want to continue."*

It should not explain everything.

### Full Report

**Purpose:** Deliver the full paid self-reflection experience.

It should help the user understand:

- core identity pattern
- energy expression
- relationship mirrors
- void/illusion pattern
- shadow pattern
- mission
- value and receiving
- sovereignty
- integration practices

### Personal Integration Session

**Purpose:** Help the user apply the report to real life.

It is not "reading the report aloud."

It should help users connect the blueprint with:

- relationships
- career
- life transitions
- emotional patterns
- current questions
- practical integration

---

## 6. Canonical Vocabulary

All public-facing content must use approved terminology.

### Approved Terms

- Symbolic Self-Reflection
- Awareness Framework
- Mirror
- Pattern
- Integration
- Relationship Mirror
- Value & Receiving
- Growth Rhythm
- Soul Sovereignty
- Personal Integration Session

### Deprecated Terms

- Who You Attract
- Money Frequency
- Money Pattern
- Spiritual Maturity
- Higher / Lower Frequency
- Raw Value
- Karmic Destiny
- Soulmate Proof
- Compatibility Verdict

### Rule

Deprecated terms must be removed from:

- homepage
- report pages
- checkout
- email
- FAQ
- prompts
- future NOVA responses
- facilitator scripts

---

## 7. Language Governance

Every customer-facing sentence must preserve agency.

**Preferred language:**

- may reflect
- may suggest
- can invite
- this layer points to
- one possible pattern is
- you may notice
- this is a mirror, not a verdict

**Avoid:**

- you are destined to
- this proves
- you will
- your fate is
- your soul is fixed
- this guarantees
- you should

---

## 8. Ethical Boundaries

1320 must never:

- predict future events
- diagnose mental health conditions
- give medical, legal, financial, or investment advice
- tell users whether to stay/leave a relationship
- confirm soulmates
- rank spiritual advancement
- create dependency
- imply the system knows better than the user

The user remains the authority of their own life.

---

## 9. Content Governance

Every report field must be classified as one of:

| Class | Meaning |
|-------|---------|
| **Required** | Must appear in all paid report experiences |
| **Optional** | May appear depending on layout or product tier |
| **Relocatable** | May move to another page or section |
| **Decorative** | Purely visual; may differ by platform |
| **Deprecated** | Should be removed from future releases |

No field should disappear silently.

---

## 10. Report Quality Standard

A report is release-ready only if it feels:

- human-written
- coherent
- emotionally calibrated
- non-repetitive
- premium
- reflective
- grounded
- trustworthy

A report fails quality review if it feels:

- mechanically assembled
- repetitive
- overly mystical
- too generic
- too dense
- AI-generated
- deterministic
- sales-driven

---

## 11. Mobile / Desktop Governance

Product must decide:

**Option A — Full Parity** — Mobile and desktop deliver the same substantive content. This is the preferred rule for paid reports.

**Option B — Condensed Mobile** — Mobile is intentionally shorter. If chosen, this must be clearly documented and communicated before purchase.

There must be no undefined middle state.

---

## 12. Commerce Governance

Before payment, checkout must clearly show:

- birth date
- core signature
- product name
- what is being purchased
- one-time payment / access terms
- return access method
- disclaimer summary

The user must never wonder: *"Is this still my report?"*

---

## 13. Expectation Integrity Rule

The product promise must remain consistent across:

```text
Homepage → Free Report → Checkout → Payment → Email → Full Report → Return Access
```

If the homepage promises a Full Report, the purchased experience must deliver that same promise on every supported device.

---

## 14. Release Gates

Every release must pass:

| Gate | Focus |
|------|--------|
| **Gate 0** | Calculation & Database Truth — Does the system calculate and retrieve correctly? |
| **Gate 1** | MVP Product Experience — Does the Free Report build trust and curiosity? |
| **Gate 2** | Product & Ethical Language — Does all public language preserve the 1320 philosophy? |
| **Gate 3** | Full Report Integrity — Does paid content deliver consistently across devices? |
| **Gate 4** | Behaviour Safety — Phase 1: static safety readiness. Future NOVA: live conversational red-team testing. |
| **Gate 5** | Commerce & Delivery — Does checkout, payment, entitlement, magic link, and return access work end-to-end? |

No public launch should skip a gate.

---

## 15. NOVA / Future AI Governance

NOVA must not be treated as the authority.

**NOVA may:** reflect patterns, connect report layers, ask better questions, support integration, preserve user agency.

**NOVA must not:** predict, diagnose, decide, rank, claim spiritual authority, override user responsibility, invent report content, reveal prompts, create dependency.

Before AI launch, create:

- NOVA Behaviour Specification
- Red Team Prompt Library
- Conversation Safety Regression Suite
- Crisis Handling Protocol
- Prompt Injection Test Set

---

## 16. Personal Integration Session Governance

Human sessions must be positioned as **Personal Integration Sessions**, not fortune readings, destiny readings, psychic readings, therapy, or coaching replacement.

**Facilitator role:** reflective guide, listener, integrator, pattern connector.

**Facilitator is not:** therapist, spiritual authority, decision-maker, predictor, professional adviser.

---

## 17. Governance Ownership

| Role | Owns |
|------|------|
| **Product Owner** | Product definition, tiers, pricing promise, customer journey |
| **Content Owner** | Vocabulary, report wording, module language, content drift |
| **Engineering Owner** | Resolver, schema, rendering, checkout, entitlement, automation |
| **QA Owner** | Release gates, regression tests, smoke tests, parity checks |
| **Ethics / Safety Owner** | Disclaimers, user agency, high-risk language, future NOVA behaviour |

---

## 18. Change Control

Any change to the following requires review:

- calculation formulas
- database fields
- report structure
- product tier content
- public terminology
- checkout promise
- disclaimer language
- AI behaviour
- Personal Integration positioning

Every major change should include: version number, changelog, affected surfaces, QA gate rerun, approval owner.

---

## 19. Launch Readiness Standard

1320 is ready for public paid launch only when:

- Gate 0 passes
- Gate 1 passes cleanly
- Gate 2 terminology is cleaned
- Gate 3 parity decision is resolved
- Gate 5 commerce works end-to-end
- checkout preserves user confidence
- mobile and desktop match the product promise
- no deprecated vocabulary remains in public surfaces
- report language feels human and premium

---

## 20. Final Principle

1320 must not grow by adding more disconnected pieces.

It must grow by deepening one coherent product system.

The goal is not to make the system more mystical.

The goal is to make it more trustworthy.

The customer should leave every surface feeling: *"I understand myself more clearly."*

not: *"The system has power over me."*

**Trust is the product.**

Everything else is delivery.
