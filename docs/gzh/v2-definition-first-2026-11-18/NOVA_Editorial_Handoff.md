本交接包 **只有全 258 碼共用的編輯規格，以及 S1-18「轉化者」一個實際完整示範**；它不是 258 碼全部已深化，也不是已核准資料。

## 版本管理與匯入安全
- 不覆寫 S0～S6 既有 RC1／RC2／RC3.2 入庫記錄，也不覆寫真人「基本通過」閱讀記錄。
- 此示範歸檔為新的 Definition-First 編輯候選，獨立版本欄位，不得映射至已發佈顧客欄位。
- `editorial_status=PENDING_REVIEW`、`reviewer=null`、`approved_at=null`、`customer_publishable=false`、`live_release_approved=false`。
- 僅限受保護內部 Preview；不能推出任何正式系統核准或發佈權限。
- 來源錨點只應保存在 INTERNAL；不要將原始 `source_text_internal` 輸出至任何顧客呈現層。
- 每個 Code 的完整定義只能以該碼的原始 source fields 撰寫；不因示範而複製 S1-18 的定義到其他 Code。
- 待真人逐碼審閱新增內容後，才能考慮新版本的正式內容簽核；簽核與顧客發布為獨立關卡。

## 建議的製作順序
1. 先鎖定這份「定義 → 意義 → 作用／反思目的 → 生活案例 → 領悟」欄位與驗收標準。
2. S7、S8、S9 尚未撰寫的批次可從第一稿就採用新標準。
3. S0～S6 的既有短篇／母稿保留不變，追加 `complete_definition` 等欄位形成新候選版本，對新增段落逐碼人工審閱。
4. Sample 與 Full 都先說清楚 Code 定義；同時對跨碼重複內容做精簡，不把十篇原型定義生硬重複。
