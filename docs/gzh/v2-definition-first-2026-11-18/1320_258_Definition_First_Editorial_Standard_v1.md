## 核心問題與新的閱讀順序

現有 RC1／RC2／RC3 候選稿已包含短篇或七項母稿欄位，但讀者可能先遇到生活例子，仍未建立「原型是什麼」的清晰概念。因此，**每一碼必須先解釋自身，再提供生活對照**。

1. **定義：它是什麼？** 用原始來源支持的具體語言解釋，不用循環定義（「轉化者是會轉化的人」）。
2. **意義：它代表什麼？** 點明這個 Code 的核心象徵、內部構成及與近似 Code 的差別。
3. **作用：在所屬模組的生命藍圖中看見什麼？** 定義模組功能，不將所有 Code 視作固定人格。
4. **目的：此段閱讀想協助讀者探索哪個問題？** 「目的」是編輯／反思用途，不是宇宙使命、命運分派、必然人生結果。
5. **力量與張力：哪一面值得探索、哪一面需要辨認？** 使用條件式及可能式，不作診斷。
6. **日常對照與例子：至少兩個具體而不同的假設情境。** 標明虛構，不暗示為讀者真實經歷；例子必須扣回前面的定義。
7. **領悟與整合：從例子回到理解。** 以可選擇的小步驟及反思問題收尾；不承諾成效。

## 每碼標準欄位（建議的唯一中文母稿）

| 欄位 | 定義與驗收標準 |
|---|---|
| `code`、`module`、`name_zh_tw_candidate` | 原始碼值不改，中文名稱保留版本資訊 |
| `one_sentence_definition` | 一句話能辨認本碼與近似碼的不同 |
| `complete_definition` | 具體解釋「是什麼、如何理解、不是什麼」；建議約 200–350 字，依來源資訊密度調整 |
| `symbolic_meaning` | 核心象徵及原文依據；不把象徵說成可驗證的超自然能力 |
| `role_within_module` | 在 S0–S9 的模組角色，避免錯置到其他模組 |
| `reflective_purpose` | 讀者透過此碼可探索的問題；不寫作人生註定目的 |
| `distinct_from` | 與至少一個易混淆 Code 的具體差異；不可自行改映射 |
| `strength_and_possibilities` | 有條件的建設性表達，不保證一定擁有 |
| `tensions_and_limits` | 可能的代價或盲點，不污名化、不推責 |
| `meaningful_shift` | 原型從張力轉向可行選擇的關鍵領悟 |
| `everyday_examples` | 至少 2 個不同領域的**假設案例**；每個案例含情境、可能反應、可供思考的變化；非讀者履歷 |
| `integration_practice` | 一項可選擇、不冒險、不侵犯他人自主權的日常練習 |
| `reflection_questions` | 建議 2–3 題，使用者可自行判斷符合程度 |
| `misreading_and_boundaries` | 防止誤讀、過度承諾、命定化／專業替代 |
| `source_field_anchors`、`source_file_sha256` | 追溯每個核心主張的真實欄位與原始版本；來源材料僅 INTERNAL |
| `editorial_status` 等發布閘門 | `PENDING_REVIEW`、`reviewer=null`、`approved_at=null`、`customer_publishable=false` |

**呈現順序：** 名稱／一句話定義 → 完整定義 → 代表什麼 → 在本模組中的作用與反思目的 → 力量／張力 → 日常對照 → 領悟與整合 → 反思問題 → 必要邊界。  
**建議篇幅：** FULL 報告中每碼約 700–1100 字的中文敘事（視來源密度與篇章去重調整）；Sample 可使用經真人審核的濃縮版，但保留「定義先行」的次序。不要為湊字數捏造新的象徵。
